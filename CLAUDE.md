# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
pnpm dev            # registry:build + icons:build, then next dev (~30s before it listens)
pnpm build          # same prebuild, then next build
pnpm registry:build # `shadcn build` — regenerates public/r/*.json from registry.json
pnpm icons:build    # regenerates the public/hugeicons/ manifest + shards
pnpm typecheck      # tsc --noEmit
pnpm lint           # eslint
pnpm format         # prettier --write "**/*.{ts,tsx}"
```

There is no test suite; `typecheck` + `lint` are the verification steps.

After editing `registry.json`, run `pnpm registry:build` by hand — `public/r/` is gitignored and only regenerated by that command (or a full dev/build start).

The dev server is usually already running on port 3000. Check `lsof -nP -iTCP:3000 -sTCP:LISTEN` before starting another. Starting via the `registry` launch config often times out because of the prebuild chain; `./node_modules/.bin/next dev -p 3000` binds in ~1s when the generated artifacts already exist.

## Architecture

A shadcn/ui **registry** app (style `base-nova`, Base UI primitives, Tailwind v4, HugeIcons, RTL on), structured after Vercel's `registry-starter`. It is both the design system's source of truth and the site that browses it.

### The registry pipeline

`registry.json` (183 items, including 71 showcase `<name>-card` blocks generated from `app/(registry)/cards/`: `registry:ui`, `registry:component`, `registry:block`, `registry:example`, one `registry:theme`, one `registry:style`) is the manifest. `shadcn build` reads it and emits `public/r/<name>.json`, which is what consumers install (`@aiellie/<name>` namespace, see [lib/mcp-config.ts](lib/mcp-config.ts)). Registry items reference each other by absolute URL (`https://registry.aiellie.dev/r/theme.json`), not bare names.

Source files are read straight from disk at request time — [lib/registry-server.ts](lib/registry-server.ts) resolves each item's `files[].path`, reads content, Shiki-highlights it, and builds the file tree that [components/registry/block-viewer.tsx](components/registry/block-viewer.tsx) renders. So the code shown on the site is always the working tree, never a snapshot.

### Two routing halves

- `app/(registry)/` and `app/(home)/` — the browser shell: sidebar + header + `BlockViewer`. Item pages at `/registry/<name>`; design tokens at `/tokens`, icon explorer at `/icons`.
- `app/demo/[name]/` — the live previews, loaded by `BlockViewer` in an `<iframe src="/demo/<name>">`. Theme stays in sync with the parent window because next-themes listens for `localStorage` storage events across the frame boundary.

### Demo files are dual-purpose

Files under `app/demo/[name]/ui/*.tsx` and `.../components/*.tsx` are both the iframe preview **and** the `registry:example` payload (targeted at `components/examples/<name>-example.tsx` for consumers). They default-export a component that lays out variants with `ExampleWrapper` / `Example` from [components/example.tsx](components/example.tsx). The demos map in `app/demo/[name]/index.tsx` also accepts an object form `{ components: { Default, … } }`, used by blocks.

### Where components live

- `components/ui/` — the base-nova shadcn primitives (`registry:ui`).
- `components/ai-elements/`, `components/ai/`, `components/canvasui/`, `components/brand/` — richer items that still ship to `components/ui/` or `components/` on the consumer side; the registry entry's `target` decides.
- `components/registry/` — the browser shell itself (block viewer, Open in v0, MCP dialog, sidebar). Not distributed.
- `registry/common/` — files distributed with the `theme` item (globals.css, typeset.css, utils.ts, tsconfig/postcss/package fragments). `registry/common/globals.css` is the distributable mirror of `app/globals.css`; re-sync it when theme tokens change.

### Sidebar metadata

[lib/items.ts](lib/items.ts) is the single source of truth for each item's icon, curated category, and `isNew` flag — separate from `registry.json`, which only carries title/description/files/deps. The sidebar can group by registry `type` or by `category`.

### Generated, gitignored artifacts

`public/r/` (registry payloads) plus `public/hugeicons/` (icon manifest + 128-icon shards, content-addressed by package version — see [scripts/build-icons.mjs](scripts/build-icons.mjs)). `/icons` browses that set; the manifest also carries HugeIcons' category taxonomy, scraped into `data/hugeicons-categories.json`. Those same 59 categories are what [lib/icons.ts](lib/icons.ts) files the curated catalog under.

## Adding a registry item

All four registrations are required:

1. The component file (e.g. `components/brand/brand-avatar.tsx`).
2. A demo at `app/demo/[name]/{ui,components}/<name>.tsx`, registered in the `demos` map in `app/demo/[name]/index.tsx`.
3. A `registry.json` entry — `getRegistryItem(name)` throws without it, so `/demo/<name>` 404s even when the demos map has it.
4. A `lib/items.ts` entry (icon, category, `isNew`).

Then `pnpm registry:build`. View it at `/registry/<name>` — the landing page hides the sidebar.

## Conventions

Read `node_modules/next/dist/docs/` before relying on Next.js API knowledge; this is Next 16 with Turbopack and may differ from training data (see [AGENTS.md](AGENTS.md)).

Base UI (`base-nova`) differs from Radix-based shadcn in ways that bite repeatedly:

- Composition uses `render`, not `asChild`: `<Button render={<Link href="/x" />} nativeButton={false}>`. Omitting `nativeButton={false}` on link renders logs a console error.
- State attributes are `data-open` / `data-panel-open`, not `data-[state=open]`.
- `CommandDialog` does not wrap children in `<Command>` — add it yourself or cmdk crashes.
- `DropdownMenuLabel` (Base UI `Menu.GroupLabel`) must sit inside a `DropdownMenuGroup`, else the menu crashes on open.
- `ToggleGroup`'s `onValueChange` receives an array and `defaultValue` must be an array; there is no `type="single"`.
- `Combobox` only filters items it owns — pass data via `Root items=` and render through the function children of `Combobox.List` / `Combobox.Collection`.
- `input-otp` has no `"use client"` banner and calls `createContext` at module scope; never import its constants into a server module.

Other repo-wide rules:

- Icons are HugeIcons: `<HugeiconsIcon icon={XIcon} strokeWidth={2} />`. Verify the name exists in `@hugeicons/core-free-icons` before using it (e.g. `Settings01Icon`, not `SettingsIcon`).
- RTL is enabled — use logical utilities (`ms-`/`me-`/`ps-`/`pe-`/`start-`/`end-`) and `rtl:rotate-180` on directional arrows. RTL-specific examples live in `examples/rtl/`.
- Prettier: no semicolons, double quotes, 80 cols, with `prettier-plugin-tailwindcss` sorting classes against `app/globals.css` (`cn`/`cva` included).
- Theme tokens live only in `app/globals.css` (`@theme inline` + `:root`/`.dark` oklch vars); never hardcode colors in components.
